Audit the current Application Health implementation against the existing health model/spec in the repository.

Do NOT redesign the architecture and do NOT add new resource kinds yet.

First:
1. Trace the complete data flow from useProjectResources/useKubeLists through resource classification, evaluateApplicationHealth, multi-cluster aggregation, ApplicationHealth, Health column, and ApplicationStatusPopover.
2. Verify that health-bearing resources are the only resources contributing to the primary application health verdict.
3. Verify that ReplicaSet, Service, Endpoints, EndpointSlice, CronJob, and HPA are supporting resources only and do not independently vote on application health.
4. Verify that ownership attribution follows Pod -> ReplicaSet -> Deployment where applicable.
5. Identify any double-counting or duplicate findings.
6. Review PVC and Job semantics carefully:
   - A PVC should only affect application health when it is actually relevant to the application's workloads.
   - Historical/irrelevant failed Jobs should not incorrectly make an otherwise healthy application unhealthy.
7. Review Unknown semantics. Do not turn the entire application Unknown merely because one resource kind is loading or one API request failed if sufficient evidence exists to determine health.
8. Distinguish "unhealthy" from "unobservable". 401/403/404/5xx/timeouts should produce observability gaps where appropriate rather than inventing health failures.
9. Verify Service/Endpoints/EndpointSlice handling. They may generate supporting connectivity findings, but must not duplicate Pod readiness as health votes.
10. Review multi-cluster aggregation and verify that an unreachable cluster is represented as Unknown/observability gap rather than silently treated as Healthy.
11. Add or update unit tests for every edge case above.

Do not modify code until you have first reported:
- what is currently correct,
- what is incorrect,
- what is ambiguous,
- and the exact files/functions that need changes.

Then implement only the necessary fixes and run the relevant tests.
