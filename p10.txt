WHY THIS TAKE-2 EXISTS (learn from the last run's mistakes — be critical)
--------------------------------------------------------------------------------
The previous live run was honest but produced NO usable numbers because:
  (a) the capture was only a few seconds, not the required minutes;
  (b) it concluded "resource timing returned no entries because requests use
      proxied fetch paths" — THAT CONCLUSION IS WRONG. The calls to
      /clusters/<cluster>/... are SAME-ORIGIN on localhost:3000, so the browser
      Performance API DOES record their full timing (including duration). The
      script below reads exactly those entries, so latency + overlap CAN be
      measured without any DevTools-waterfall eyeballing.
So this file removes the guesswork: paste one script, wait the real duration,
read the printed numbers.

Endpoints you will see (proxied form in the browser):
  - Kubernetes version:  /clusters/<cluster>/version                 (GET)
  - Auth check (SAR):    /clusters/<cluster>/apis/authorization.k8s.io/v1/
                         selfsubjectrulesreviews                      (POST)
     NOTE: SAR returns HTTP 201 on success (it "creates" a review) — 201 is
     GOOD, not an error. Timed-out request => 408; unreachable backend => 502.
  - OCP version:         /clusters/<cluster>/apis/config.openshift.io/v1/
                         clusterversions/version                      (GET, ~1h)

STEP 2 — MEASURE LATENCY (A) + OVERLAP (B)  [the two most important numbers]
================================================================================
2.1  Click into the DevTools "Console" tab.
2.2  COPY the entire script block below and PASTE it into the Console, press
     Enter. It only reads performance entries — it sends nothing, changes
     nothing.

----- BEGIN SCRIPT (paste as-is) ----------------------------------------------
(() => {
  const hits = [];
  const obs = new PerformanceObserver(list => {
    for (const e of list.getEntries()) {
      if (/\/version(\?|$)|selfsubjectrulesreviews|clusterversions/.test(e.name)) {
        const m = e.name.match(/\/clusters\/([^/]+)\//);
        hits.push({
          key: e.name.replace(/https?:\/\/[^/]+/, '').split('?')[0],
          cluster: m ? m[1] : '?',
          start: e.startTime,
          ms: e.duration,
        });
      }
    }
  });
  obs.observe({ type: 'resource', buffered: true });
  window.__stop = () => {
    obs.disconnect();
    const pct = (a, p) =>
      a.length ? Math.round(a.slice().sort((x, y) => x - y)[Math.min(a.length - 1, Math.floor(p * a.length))]) : null;
    console.log('=== LATENCY (ms) ===');
    for (const k of ['/version', 'selfsubjectrulesreviews', 'clusterversions']) {
      const a = hits.filter(h => h.key.includes(k)).map(h => h.ms);
      console.log(k, 'count=' + a.length, 'p50=' + pct(a, 0.5), 'p95=' + pct(a, 0.95),
        'max=' + (a.length ? Math.round(Math.max(...a)) : null), '>5s=' + a.filter(x => x > 5000).length);
    }
    console.log('=== OVERLAP (B) ===');
    const sar = hits.filter(h => h.key.includes('selfsubjectrulesreviews')).sort((a, b) => a.start - b.start);
    let overlaps = 0, gaps = [];
    for (let i = 1; i < sar.length; i++) {
      if (sar[i].cluster === sar[i - 1].cluster) {
        const prevEnd = sar[i - 1].start + sar[i - 1].ms;
        if (sar[i].start < prevEnd) overlaps++;
        else gaps.push(Math.round(sar[i].start - prevEnd));
      }
    }
    console.log('same-cluster SAR overlaps =', overlaps, '(0 = no overlap / single-flight confirmed)');
    console.log('gaps between consecutive same-cluster SAR (ms) =', gaps);
    return hits;
  };
  console.log('capturing… stay on All Clusters. After 3-5 minutes run:  __stop()');
})();
----- END SCRIPT --------------------------------------------------------------
