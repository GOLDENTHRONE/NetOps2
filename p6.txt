WHAT CHANGED (context for the reviewer)
------------------------------------------------------------------------------
Two feature commits are on GT_D_V1 (tips: 4d58b78, e71900c):

1) "Truthful cluster readiness + auto-check all clusters"
   - New hook useClustersAuth (frontend/src/lib/k8s/index.ts): a background
     authorization probe per connected cluster — POST
     /apis/authorization.k8s.io/v1/selfsubjectrulesreviews via testAuth().
     testAuth uses autoLogout=false, so a 401 here must NOT clear the global
     session.
   - getClusterReadiness / getClusterReadinessLabel + Inventory info/accessor
     (Home/clusterStatus.ts, Home/ClusterInventory/index.ts): combine
     reachability (/version) with authorization into the status labels:
        Ready | Reachable | Authentication required | Insufficient permissions |
        Unavailable | Control plane unhealthy | Not connected | Connecting…
   - OCP ClusterVersion now polls every 1 hour (was 10s): index.ts
     ocpVersionFetchInterval / ocpVersionRefetchInterval.
   - AUTO_CONNECT_ALL (default true): every configured cluster is checked on
     page open (upstream Headlamp behaviour), not only recently-used ones.
   - The cluster NAME link is always clickable (never blocked while connecting).

2) "Centered access gate when opening a cluster"
   - New component ClusterAccessGate (frontend/src/components/cluster/
     ClusterAccessGate.tsx): one centered screen with states
     checking / unreachable / expired (401) / forbidden (403), dynamic (i18n)
     messages, a "Back to All Clusters" button always present, plus
     "Sign in again" (expired) and "Retry" (unreachable), and an expandable
     "Technical details" block.
   - AuthRoute (frontend/src/components/App/RouteSwitcher.tsx) renders the gate
     for the pending and non-OIDC error cases instead of a blank page / hard
     redirect. OIDC keeps its existing auto-redirect login flow. Success still
     renders the cluster. Multi-cluster + requires-auth short-circuits unchanged.

3) "Fix: use static ESM import for ResourceClasses instead of require()"
   (commit f67d831) — a SEPARATE, PRE-EXISTING crash fix, not part of the
   feature above.
   - Symptom: opening ANY cluster crashed with
     "ReferenceError: require is not defined" and the error boundary
     "Uh-oh! Something went wrong. Error loading Cluster".
   - Cause: event.ts / crd.ts / hpa.ts / vpa.ts called require('.') inside a
     method. require is a Node API and does not exist in the browser (Vite/ESM)
     runtime. It was introduced by commit 17075cc (BEFORE the feature work), so
     it is NOT caused by items (1) or (2).
   - Fix: restored the static `import { ResourceClasses } from '.'` in those
     four files and removed the require() calls. (node.ts was already correct.)

Config knobs (Vite env, all optional; defaults chosen for this change):
   REACT_APP_AUTH_CHECK_INTERVAL          (ms, default 10000)
   REACT_APP_OCP_VERSION_FETCH_INTERVAL   (ms, default 3600000 = 1h)
   REACT_APP_AUTO_CONNECT_ALL             (default true)
   REACT_APP_ENABLE_READY_CHECK           (default true)
