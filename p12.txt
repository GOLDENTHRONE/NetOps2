--------------------------------------------------

Implement real Applications-local evaluation.

ReplicaSet:

Pod:

- Ready condition

- CrashLoopBackOff

Job:
evaluate:

- succeeded
- failed
- active

PVC:

- Bound
- Pending
- Lost

--------------------------------------------------
STEP 6 — Final aggregation
--------------------------------------------------

Use this precedence:

CHECKING
→ UNHEALTHY
→ DEGRADED
→ UNKNOWN
→ HEALTHY
→ NO RESOURCES

But NO RESOURCES is a separate terminal state and must only be selected after fetching has completed and there are no relevant resources.

UNHEALTHY means a definitive health-bearing failure exists.

Examples:

- failed Pod
- definitive Deployment failure
- ready replicas = 0 where workload requires replicas
- Failed Job
- Lost PVC

DEGRADED means a non-definitive/partial health problem exists.

UNKNOWN means the resource exists but its health cannot reliably be evaluated because of:

- RBAC/API error
- missing required status information
- another genuine evaluation uncertainty

Do NOT use UNKNOWN merely because a resource kind has no health evaluator.

Informational-only resources are NOT automatically UNKNOWN.
