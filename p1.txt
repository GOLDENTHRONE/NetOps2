BACKGROUND (what is changing and why)
------------------------------------------------------------------------------
The Applications tab lives at:
  - list:    route "/projects"        -> frontend/src/components/project/ProjectList.tsx
  - details: route "/project/:name"   -> frontend/src/components/project/ProjectDetails.tsx
  - route def: frontend/src/lib/router/index.tsx  (key: projectDetails)

Today an "application" = a namespace name. Namespaces with the SAME NAME across
multiple clusters are COLLAPSED into one row, and health is computed over the
pooled resources of all those clusters (one worst-wins verdict). See
discoverProjectsFromNamespaces() in ProjectList.tsx.

PLANNED CHANGE (the "flat" model):
  One row per (cluster, namespace). Each row = one application instance in
  exactly ONE cluster and ONE namespace, with its OWN independent health.
  i.e. discoverProjectsFromNamespaces() should emit one ProjectDefinition per
  (cluster, namespace): id = `${cluster}/${namespace}`, clusters:[cluster],
  namespaces:[namespace]. Plus a "Cluster" table column. The health logic
  (localHealth.ts / getLocalHealth / localGetItemStatus) needs NO change.

The concern we are verifying: does this touch the "All Clusters" tab (Home,
route "/") or any other tab? Prove yes/no with evidence.
