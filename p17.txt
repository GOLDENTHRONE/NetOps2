WHY THIS TEST
-------------
On the All Clusters tab, a row shows "Authentication required" only when a poll
returns HTTP 401 (verified in code: clusterStatus.ts -> getClusterReadiness,
auth.error.status === 401 / versionError.status === 401).

The frontend recovery logic is already verified (code + simulator): every poll
overwrites the stored error, so the instant ONE poll returns 200 the row flips
to "Ready". So if the row stays stuck at "Authentication required" while polling,
one of exactly two things is true:

  (A) the live polls are STILL returning 401  -> the token the BACKEND presents to
      the cluster is still bad for this session (backend token/session caching).
      A full page reload starts a fresh session and returns 200 -> "Ready".
  (B) the live polls are returning 200 but the UI still shows auth-error -> a
      FRONTEND state bug (needs deeper digging).

This test reads the actual response status/body to decide A vs B. It does NOT
change any code.

The two polls to watch (fire every ~10s, backing off to at most ~60s):
  - GET  /clusters/<cluster>/version
  - POST /clusters/<cluster>/apis/authorization.k8s.io/v1/selfsubjectrulesreviews
  (OCP-only extra, harmless if 404):
  - GET  /clusters/<cluster>/apis/config.openshift.io/v1/clusterversions/version

 NOTES (honest scope)
===============================================================================
- "Authentication required" == HTTP 401 (clusterStatus.ts). 403 == "Insufficient
  permissions"; timeouts/5xx == "Unavailable".
- testAuth is sent with autoLogout=false, so a 401 here never logs you out or
  clears the session by itself (clusterApi.ts:40, clusterRequests.ts:201).
- The frontend does NOT hold the OCP token; it proxies to the backend with
  cookies + a backend token, and the backend attaches the OCP credential. So
  live vs reload send identical credentials — which is why a live-401/reload-200
  split points at the backend, not this frontend.
- This test only READS responses; it changes no code and is safe to repeat.
