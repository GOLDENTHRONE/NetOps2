We need to determine exactly what happens when a cluster is reachable but Namespace discovery fails, for example because the user does not have permission to list namespaces (403), or because the namespace API returns another error.

The previous investigation suggests that:

- Applications are dynamically derived from successful Namespace discovery.
- A failed Namespace list produces no namespace objects.
- No ProjectDefinition/Application row is created for a namespace that is known only to exist on the failed cluster.
- Health-resource queries therefore do not start for that missing Application.
- Existing allowedNamespaces/localStorage data is not currently a general authoritative Application inventory.
- A cluster-level "Namespace inventory unavailable" state may therefore be more semantically correct than fabricating an Application row.
